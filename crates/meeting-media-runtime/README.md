# meeting-media-runtime

音声取得・録音 worker と推論 worker の制御、PCM 中継を所有する Rust ライブラリです。
`meeting-desktop-runtime` が直接利用し、音量・確定した文字起こしを画面へ配信します。
起動方法は [Rust バックエンド](../../doc/development/rust-desktop-backend.md)を参照してください。

## 所有権と障害の分離

[Rust バックエンドの直接接続](../../doc/development/rust-desktop-backend.md)では、
入力元ごとの `Supervisor` が音声取得 worker を所有し、`SharedSpeech` の推論 worker を共有します。
選択した認識モデルと任意の句読点モデルはそれぞれ 1 つだけ読み込みます。
VAD の状態・発話バッファ・サンプル位置は入力元ごとに保持し、推論とは別の thread で更新します。
完成した発話の推論は両入力を通じて直列です。

モデルは「音声認識を準備」の操作で読み込み、Whisper はウォームアップも完了させます。
停止時は両入力を切り離して残る音声と末尾の認識を処理し、準備済み状態に戻ります。
会議間でモデルを保持し、準備解除・設定変更・終了時に解放します。

- 音声取得と WAV 書込みは、モデル準備・推論とは別のプロセスです。
- PCM キューは 2000 フレーム（60 秒）で制限します。あふれや音声の連番欠落を検知した場合は推論を失敗扱いにします。
- 共有 worker の推論待ちは最大 16 件で、処理中を含む発話音声は合計 60 秒までです。上限超過や推論障害時は両入力の認識を停止し、録音は継続します。
- 認識結果は世代とサンプル位置を検証し、古い結果や順序の不整合を拒否します。
- 停止応答より前に末尾の認識結果を配信します。会議 runtime も会話処理への引渡しを待って停止を完了します。
- モデル準備は中断できます。推論の停止・再準備は録音プロセスを終了しません。
- 音声取得の通信異常時は取得 worker を終了し、成功した録音として扱いません。
- Linux では親終了通知を設定し、制御プロセスの突然の終了でも子プロセスを残しません。
- 子プロセスには用途に必要な環境変数だけを渡します。標準エラーや音声内容をログへ転送しません。

## 検証

```bash
cargo test --locked --manifest-path crates/meeting-media-runtime/Cargo.toml
cargo test --locked --manifest-path crates/meeting-desktop-runtime/Cargo.toml
```

連番欠落、不正なパケット長、停止時の末尾処理、録音と推論の障害分離を合成ワーカーで確認します。
実機のデバイス・認識品質とは分けて検証します。
