# Security Policy

## Supported versions

Meeting Supporter has not published a release. Only the current `main` branch is supported for security fixes.

| Version | Supported |
| --- | --- |
| `main` | Yes |
| Unreleased snapshots and older commits | No |

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability. Use [GitHub Private Vulnerability Reporting](https://github.com/ouvill/meeting-supporter/security/advisories/new).

If Private Vulnerability Reporting is unavailable, email `contact@ouvill.net`. Do not include credentials, tokens, personal information, meeting transcripts or audio, secret-bearing raw stderr, or other sensitive payloads in the initial message. Use synthetic data and provide only the minimum information needed to establish the affected component and impact; maintainers will arrange a safer channel if more detail is required.

Please include, when safe:

- the affected component and commit or version;
- the security impact and required preconditions;
- minimal reproduction steps using synthetic data;
- whether the issue is already public or known to be exploited.

## Coordinated disclosure

Keep the report and non-public remediation details confidential until a fix or security advisory is published. Coordinate public disclosure with the maintainers so users can obtain the fix first. This policy does not promise a particular acknowledgement or remediation time.

Good-faith reports that follow this process are appreciated. Do not access data that is not your own, disrupt services, degrade other users' systems, or use production credentials while investigating.
