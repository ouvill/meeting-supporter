# ADR-020: Rust の設定をバージョン付きの専用形式にする

- **Status**: Accepted
- **Date**: 2026-10-01
- **Partially supersedes**: ADR-009 の設定バージョン、ADR-016 の設定・認証情報の引き継ぎ、ADR-019 の Rust における旧設定の扱い

## Context

製品は未リリースであり、開発中の設定を再入力することを許容する。
Python と Rust で旧設定の読み替えや廃止項目の除外を維持すると、機能を整理しても互換処理が残る。
Rust への切り替えを設定形式の区切りにする。

## Decision

- Rust はアプリのデータディレクトリにある `settings.toml` だけを設定として読む。
- ファイル全体に整数の `schema_version = 1` を必須とする。アプリの版とは独立させ、形式や意味を非互換に変更するときに更新する。
- 既定値・型・値の検証は Rust が所有する。Python の既定設定ファイルを参照しない。
- ファイルが存在しない場合は現在の既定値で起動し、設定を保存したときに新形式のファイルを作成する。
- 未知の項目、廃止済みの方式、不正な値は拒否する。バージョンがないファイルや対応外のバージョンも読み替えず、元のファイルを上書きしない。
- 旧 `config.toml` は読み込まず、書き換えない。旧形式向けの移行処理や変換の枠組みは実装しない。
- API キーは OS の認証情報ストアだけを使用する。旧 `secrets.toml` の読み込み・移行・削除と、Rust での `SECRET_STORE_BACKEND=file` は提供しない。
- 会議履歴、録音、保存済み議事録、資料、導入済み Registry エージェント、モデルキャッシュは設定の初期化対象に含めない。

通常の設定 API は、現在の設定画面が必要とする読み取り結果と部分更新を提供する。
保存前に型・値を検証し、一時ファイルから原子的に置換する。
設定保存が失敗した場合は変更した認証情報を復元する。
OS の認証情報ストアが使えない場合もローカル設定は利用でき、BYOK の経路に認証情報ストアのエラーを表示する。

## Rejected Alternatives

- 旧形式を機能ごとに読み替え続ける案は、未リリース段階の設定保持のために通常処理を複雑にするため採用しない。
- 未知の項目を保持して再保存する案は、現在有効な設定と不要な設定を区別しにくくするため採用しない。
- 対応外のバージョンを自動的に初期化する案は、元のファイルを上書きするため採用しない。

## Consequences

Rust 構成へ切り替える際は設定をやり直す。旧ファイルは必要に応じて手動で参照・削除できる。
既存の OS 認証情報は同じストアから利用できるが、旧ファイルにしかない API キーは再入力する。
Python 構成の設定形式は Rust の正本に含めず、Python 構成の廃止とともに撤去する。
